# SEO 关键词分析指南

## 使用场景

本文档用于两个场景：

1. **主管道集成**（Step 4 子步骤）：头条 / 小红书写作完成后，通过 WebSearch 扩展相关词，为标题优化和标签生成提供真实的关键词素材
2. **独立分析模式**：用户说"帮我分析这个关键词"/"这个话题值不值得写"时，按本文档流程输出完整的关键词分析报告

**核心原则**：用 WebSearch 真实数据 + LLM 判断替代机械评分。目标是输出可操作的写作建议，而不是假精确的数字。

---

## 第一步：搜索需求判断

用 WebSearch 搜索关键词，从结果里判断真实搜索需求。

**搜索策略**（依次执行 2-3 轮）：

| 轮次 | 搜索词 | 目的 |
|------|--------|------|
| 1 | `"{关键词}"` | 看有没有真实内容，结果质量如何 |
| 2 | `"{关键词} 怎么 OR 如何 OR 推荐 OR 测评"` | 看用户主要在搜什么角度 |
| 3（可选） | `"{关键词} site:zhihu.com OR site:xiaohongshu.com"` | 看社区活跃度和讨论深度 |

**需求信号判断**：

- **强需求**：搜索结果丰富，多个平台有不同角度的内容，有明确的提问帖和讨论
- **中等需求**：有一定内容但角度单一，存在尚未被覆盖的切入点
- **弱需求**：结果稀少，或以广告 / 官方页面为主，用户搜索动机不明确

> 强需求 + 有内容空白 → 优先推荐  
> 强需求 + 已高度饱和 → 需要差异化角度才值得写  
> 弱需求 → 谨慎，除非用户有明确发布目的

---

## 第二步：搜索意图分类

根据搜索结果和关键词形态，识别主要搜索意图（可多选，取 1-2 个主要的）：

| 意图类型 | 典型关键词特征 | 对应推荐框架 |
|---------|--------------|------------|
| 教程 / 问题型 | 怎么、如何、步骤、入门、教程、设置 | 痛点解决、清单 |
| 推荐 / 对比型 | 推荐、合集、盘点、测评、哪个好、值得买 | 清单、对比 |
| 趋势 / 热点型 | 最新、2025、2026、发布、政策、行情、趋势 | 热点解读、纯观点 |
| 场景 / 人群型 | 学生党、新手、上班族、程序员、副业、宝妈 | 痛点解决、故事 |
| 泛搜索 / 品牌词 | 词义宽泛，结果多为品牌直达或百科 | 需要收窄角度后再写 |

**意图影响框架选择**：意图判断结果可在 Step 2 框架选择阶段复用，不必重复判断。

---

## 第三步：关键词扩展

基于第一步的 WebSearch 结果，提取可用于标题和标签的关键词素材。

**提取目标**：

| 类型 | 数量 | 用途 |
|------|------|------|
| 核心关键词（同义词、近义词） | 3-5 个 | 正文自然覆盖，避免重复同一个词 |
| 长尾关键词（更具体的场景/人群词） | 2-3 个 | 优先用于话题标签和标题，竞争小、命中精准 |
| 热点关联词（当前正在讨论的相关话题） | 1-2 个 | 增加时效性，适合加入头条标签 |

**提取方法**：
- 看搜索结果页面标题里的高频词汇
- 看相关推荐、"大家还搜了"类模块
- 看知乎 / 小红书 / B站结果中的话题标签

**使用原则**：
- 长尾词优先写入**标题 / 话题标签**（小红书尤重要）
- 核心关键词分散嵌入**正文**，每个词出现 2-4 次，不堆砌
- 热点关联词谨慎使用，只在与内容真实相关时加入

---

## 第四步：平台适配判断

根据话题性质，判断哪个平台效果更好。

**头条（Toutiao）更适合**：
- 深度分析、趋势解读、"为什么"类选题
- 时效性内容（政策动向、行业新闻、产品发布）
- 面向大众的通识内容，需要一定篇幅展开（800-3000 字）
- 话题有明确信息差，读者需要"解读"而非"操作"

**小红书（Xiaohongshu）更适合**：
- 场景化、生活化，和具体人群 / 使用场景强绑定的话题
- 可视化操作类内容（工具推荐、步骤攻略、好物种草）
- 情绪共鸣类（踩坑经历、亲测体验、避坑指南）
- 口语化、感性的话题，图文并茂效果更好

**Twitter / X 更适合**：
- 即时观点、吐槽、热点即时反应
- 技术 / 产品圈的专业讨论
- 有强烈个人立场的观点型内容
- 适合截图传播的金句型表达

**同时适合多个平台时**：根据用户 `config.yaml` 的 `platform` 或本次请求优先级决定，参照 Step 1 的平台判断逻辑。

## 第五步：风险识别

| 风险类型 | 识别方式 | 建议处理 |
|---------|---------|---------|
| 话题过泛 | 关键词 ≤3 字且无具体场景约束 | 加场景词收窄，如"AI工具 → 程序员用的 AI 工具" |
| 内容已高度饱和 | 搜索结果全是同质化文章，角度高度重合 | 找反直觉切入点，或换更细分的长尾词 |
| 商业 / 投机噪音高 | 结果主要是广告、招商、培训、概念股 | 调整角度或换词，避开这类词汇磁场 |
| 时效性强 | 话题与特定事件绑定（如某产品发布） | 注明内容时效，旧话题写作时需更新数据 |
| 争议 / 敏感话题 | 涉及政治、法律、医疗、金融建议等 | 明确标注，措辞中性，必要时提示用户自行核实 |
| 地域局限性强 | 内容主要在特定地区有效 | 标注地域适用范围，避免误导读者 |

## 输出格式

### 主管道集成模式（Step 4 子步骤）

输出简洁，直接供 4.1 使用：

```
【关键词扩展】
核心关键词：{词1}、{词2}、{词3}
长尾关键词：{具体词1}、{具体词2}
热点关联词：{词}（如有）
推荐标签：{5-8个话题标签，小红书格式 #话题名}
```

### 独立分析模式

用户主动请求分析时，输出完整报告：

```
【关键词分析报告】{关键词}

搜索需求：强 / 中 / 弱
  → {1句话说明依据，如"知乎有200+个问题，B站有大量教程"}

主要意图：{教程型 / 推荐型 / 趋势型 / 场景型 / 泛搜索}
推荐框架：{框架名}

关键词扩展：
  核心词：{词1}、{词2}、{词3}
  长尾词：{具体词1}、{具体词2}（竞争小，建议用于标签）
  热点词：{词}（如有）

平台适配：
  首选：{平台} — {1句话理由}
  次选：{平台} — {1句话理由}（如有）

风险提示：{列出具体风险；无则"暂无明显风险"}

写作建议：{1-2句，说明最值得切入的角度或差异化方向}
```

---

## 注意事项

- **不输出假精确评分**：不用 `X/10` 的数字评分，改用"强 / 中 / 弱"或文字判断
- **WebSearch 不可用时**：基于 LLM 训练数据判断，在输出中标注"（基于已有知识判断，未使用实时搜索）"
- **关键词分析不阻断主流程**：如果用户已明确选题且催促生成内容，可跳过完整分析，只做快速关键词扩展（3-5个相关词即可）
- **分析结论服务写作**：所有判断最终指向"用什么角度写"和"在哪里放关键词"，而不是为了分析而分析
