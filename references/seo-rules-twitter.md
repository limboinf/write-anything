# Twitter / X 可发现性优化规则

## 开场钩子

Twitter 的第一行就是标题。用户会先看到开头几行，所以首句必须直接给价值、冲突或态度。

**有效策略**：
- 结果前置：「我现在已经能自动完成……但真正的问题反而才刚开始」
- 踩坑前置：「今天第一次玩 Claude Code 的 Computer Use，先说结论：真会踩坑」
- 观点前置：「自动化越强，低质内容农场越容易泛滥」
- 吐槽/观察前置：「你们的 codex 是不是也一样，小骚话满天飞」

**避免**：
- 先铺背景、再讲重点
- 一条里塞 2 个以上核心观点
- 像文章摘要，不像人在发即时表达

**输出要求**：生成 3 个备选推文版本 + 1 个最终发布版，全部满足长度限制。

## 长度控制

- 优先控制在 **260 字以内**
- 如果有外链、emoji、hashtags，要额外留余量
- 单条短推默认不拆线程；放不下就删次要信息，不要硬塞

## 可发现性关键词与 hashtags

- 核心关键词最好出现在前 2 行，帮助站内搜索、转发截图和外部索引快速识别主题
- hashtags 控制在 **0-2 个**
- 只保留真正有帮助的搜索词或社区词，不要为了凑数堆标签
- 产品名、功能名、事件名本身往往比泛标签更有用
- Twitter / X 更重传播和互动，关键词只做自然覆盖，不做机械堆砌

## 可读性

- 3-6 行短句最佳，留出呼吸感
- 每行尽量只承载一个信息点
- 至少有 1 句可以被单独截图转发
- 允许口语、吐槽、自我修正，但不要失控到看不懂

## 互动设计

- 可以用问题句收尾，但不要每条都问
- 比起泛泛的「你怎么看」，更适合具体追问：
  - 「你们也踩过这个坑吗？」
  - 「你会选自动化产能，还是内容质量？」
  - 「你们的 codex 也这样吗？」

## 配图建议

- 配图是加分项，不是必需项
- 优先级：产品界面截图 > 信息卡片 > 抽象科技图
- 如果文字本身已经够强，可以纯文本发布
